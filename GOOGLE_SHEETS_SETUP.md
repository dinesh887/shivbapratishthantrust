# Google Sheets registration setup

The registration form is connected to a Next.js server route, which forwards validated submissions to a Google Apps Script Web App. The browser never receives the Apps Script shared secret. Until the Web App URL and secret are configured, the API returns a configuration error and the page does not claim a save succeeded.

## Form fields and validation

| Sheet column | Form field | Validation |
| --- | --- | --- |
| Registration Number | Generated by Apps Script | First column; sequential ID such as `SHB-2026-00001`; stored in the Sheet only |
| Timestamp | Generated by Apps Script | Date and time when the row is saved |
| Registration Type | Individual / Group | Required selection |
| Participant / Group Name | Name | 2–80 Unicode letters and spaces; whitespace is trimmed and collapsed |
| District / Area | District selector | Required; must match an existing option |
| Mobile | Contact number | Required, Indian mobile beginning 6–9 and exactly 10 digits; spaces are removed |
| Alternate Mobile | Optional number | Empty or a valid 10 digit Indian mobile |
| Email | Email address | Required valid address, max 254 characters |
| Fort Name | Fort being built | 2–80 Unicode letters and spaces |
| Fort Type | Four existing fort type options | Required selection |
| Google Drive Folder URL | Folder link | Required HTTPS `drive.google.com/drive/folders/...` link, max 2048 characters |
| Consent | Rules acceptance | Required checkbox |

## 1. Create the Google Sheet

1. Create a Google spreadsheet and choose the tab name (the default used below is `Registrations`).
2. Copy the spreadsheet ID from its URL. It is the value between `/d/` and `/edit`.
3. The Apps Script creates the header row on the first successful submission. Keep the sheet tab empty until then, or add the exact header row shown above yourself.

## 2. Add the Apps Script backend

1. In the spreadsheet, open **Extensions → Apps Script**.
2. Replace the editor contents with [`google-apps-script/Code.gs`](google-apps-script/Code.gs) from this project and save.
3. In Apps Script, open **Project Settings → Script Properties → Add script property** and add:
   - `SHEET_ID`: the spreadsheet ID from step 1.
   - `SHEET_NAME`: `Registrations` (or your chosen tab name).
   - `SHARED_SECRET`: a new random secret of at least 32 characters.
4. Generate a secret locally, for example with `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`. Do not commit or paste it into client code.
5. Choose **Deploy → New deployment → Web app**. Set **Execute as** to your account and **Who has access** to **Anyone**, then deploy and authorize the requested spreadsheet access. The endpoint is public at the network level, but rejects requests without the script property shared secret.
6. Copy the deployed Web App URL ending in `/exec`. If the script changes later, create a new deployment version or edit the existing deployment to use the latest version.

## 3. Configure Next.js

Create `.env.local` in the Next.js project root (it is ignored by Git) and set:

```dotenv
GOOGLE_APPS_SCRIPT_URL=https://script.google.com/macros/s/YOUR_DEPLOYMENT_ID/exec
GOOGLE_APPS_SCRIPT_SHARED_SECRET=the_same_random_secret_as_script_properties
```

Use the exact same secret in the Apps Script property and Next.js environment. Restart the Next.js server after changing environment variables. In production, set both variables in the hosting provider's server-side environment settings and redeploy. Do not use a `NEXT_PUBLIC_` prefix.

## 4. Test the integration

1. Submit the empty form. It should remain on the page, show field-specific messages, and make no request to Google Sheets.
2. Try a whitespace-only name, an invalid mobile/email, a malformed Drive link, and an unchecked consent box. Each should be rejected with a relevant message.
3. Submit a valid registration with a Drive folder link. The button should disable while sending. A success message appears only after the Apps Script confirms the row was appended.
4. Check that the row contains all fields and a timestamp. The timestamp is written as a spreadsheet date value; set the spreadsheet time zone and date-time display format to your preference.
5. To test an upstream error, temporarily use an invalid deployment URL or a mismatched secret. The page should show an error and must not show success. Restore the values after the test.

The Next.js route validates independently of the browser, requires a deployed `script.google.com/macros/s/.../exec` HTTPS URL and a shared secret of at least 32 characters, and returns a configuration error when either environment variable is missing. Google Sheets access cannot be live-verified until you deploy the Apps Script and configure your own sheet and secret.

## Duplicate registrations

Apps Script allows only one registration for a normalized participant/group name. It ignores capitalization and repeated whitespace, and checks all existing rows while holding a script lock so simultaneous requests cannot create duplicates. A repeated name is rejected even if the mobile, email, registration type, or district differs. Existing duplicate rows are not deleted; remove any old duplicates manually if you want the sheet cleaned up. After editing `Code.gs`, update/redeploy the Apps Script Web App version for the rule to take effect.

## Registration numbers

Apps Script assigns each accepted registration a sequential number in the first column (`A`, headed `Registration Number`), for example `SHB-2026-00001`. The number is written to Google Sheets only; it is not added to the website form or certificate. On an existing sheet, the script moves the existing columns to the right to make room for column A and preserves their data. Existing registrations remain blank in the new number column. Save and redeploy the updated `Code.gs` Web App version to enable this.
